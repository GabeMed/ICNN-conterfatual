================================================================================
ALGORITHM BEHAVIOR ANALYSIS
================================================================================

ECP (Extended Cutting Plane):
  - Adds cuts at infeasible points found by MILP solver
  - Each cut: γ ≥ f(x_k) + ∇f(x_k)·(x - x_k) where f(x_k) > target
  - Requires no interior point search (faster initialization)
  - Slower convergence in late iterations (many feasible-region cuts)
  - More robust (simpler logic, fewer failure modes)

ESH (Extended Supporting Hyperplane):
  - Adds cuts at interior boundary points found by Prob. MM
  - Each cut: γ ≥ f(x_k) + ∇f(x_k)·(x - x_k) where f(x_k) < target
  - Requires interior point (expensive search via Prob. MM)
  - Theoretically faster convergence with interior points
  - Falls back to ECP gracefully when interior unavailable

MILP (Full Mixed-Integer Programming):
  - Encodes full neural network structure in constraints
  - All hidden layer activations as variables
  - ReLU constraints via big-M inequalities
  - Single large optimization problem (no iterations)
  - Fast for small networks, intractable for large ones

Problem-Specific Observations:
  1. Interior points don't exist for this domain (tight constraints)
  2. ECP and ESH converge identically (same cuts generated)
  3. MILP is faster due to moderate problem size (236 features)
  4. OA methods show advantages would appear with 1000+ features
  5. Sparsity patterns consistent across methods (same important features)

================================================================================
KEY INSIGHT
================================================================================

Why ESH Didn't Generate ESH-Specific Cuts:

1. ESH requires interior point: f(x) < y_target + ε (strictly less)
2. Prob. MM searches for deepest interior point via: max ν
3. For tight constraints (40-98% reduction), no interior point exists
4. All problem instances have binding constraint at boundary
5. Therefore ESH falls back to ECP (correct behavior)
6. When ECP is used, both generate identical ECP-type cuts

When ESH Would Shine:

1. Loose constraints (5-10% cost reduction)
2. Interior points guaranteed to exist
3. Prob. MM can find deep interior points (ν >> tolerance)
4. ESH cuts provide tighter outer approximation
5. Fewer total iterations needed to converge

This Benchmark's Finding:

  Problem domain (DCOPF) has fundamentally tight constraints
  Interior points are rare for counterfactual problems
  ECP is sufficient and ESH falls back gracefully
  Both methods achieve identical solutions
  No performance penalty for ESH (actually slightly faster due to
    different solver behavior, not ESH-specific advantages)
